# Мессенджер по Bluetooth — версия 0.2

Обмен сообщениями и координатами между телефонами без интернета и сотовой связи (Bluetooth RFCOMM).

> **Важно:** версия 0.2 несовместима с 0.1 (новый протокол и новый UUID службы).
> Обновите приложение на всех телефонах.

## Что исправлено

| Было | Стало |
|---|---|
| При отказе в разрешениях кнопки «Искать», «Стать видимым», «Обновить список» роняли приложение (`SecurityException`) | Все действия с Bluetooth идут через одну проверку: разрешения → включение Bluetooth → действие. При «больше не спрашивать» — подсказка открыть настройки |
| Связь жила внутри экрана: рвалась при сворачивании, смене шрифта, разделении экрана; история пропадала | Связь держит фоновая служба (`LinkService`, foreground, тип `connectedDevice`) с постоянным уведомлением; входящие — уведомлениями |
| Сообщение могло пропасть молча (нет связи — поле очищено, а отправки нет) | Сообщение сначала сохраняется (значок часов), уходит при появлении связи. Статусы: ожидает / отправлено / доставлено (две галочки по подтверждению от собеседника) |
| При неудаче отправлялась `getLastKnownLocation` любой давности без пометки | У точки всегда есть точность (±м) и время замера; если она старше 2 минут на момент отправки — в чате пометка «⚠ точка устарела» |
| Текст `GEO:55.7,37.6`, набранный вручную, превращался в геометку | Тип сообщения — отдельное поле протокола |
| Android 11 и ниже: при выключенной геолокации поиск молча ничего не находил | Перед поиском проверяется геолокация, предлагается её включить |
| Выключение Bluetooth не отслеживалось — приём подключений тихо умирал | Отслеживается `ACTION_STATE_CHANGED`: связь корректно закрывается и сама поднимается после включения |
| «Назад» в чате разрывало связь | «Назад» возвращает к списку, связь остаётся. Отключение — в меню |
| Любой телефон с приложением подключался без спроса | Незнакомый собеседник — запрос «Принять / Отклонить» (и в уведомлении). Знакомые принимаются сразу |
| Если оба нажали «подключиться» одновременно, связь могла не установиться | Обе стороны по одному правилу выбирают одно соединение, лишнее закрывают |

## Что добавлено

- **Протокол** (`Protocol.kt`): кадр = 4 байта длины + JSON. Типы: `hello`, `accept`, `reject`, `msg`, `ack`, `ping`/`pong`, `bye`. Неизвестные кадры игнорируются — можно расширять. Формат не привязан к Java, его можно разобрать и на ESP32.
- **Профиль**: имя и должность — собеседник видит их вместо модели телефона.
- **История переписки** в SQLite (`ChatRepository.kt`), список чатов с последним сообщением и счётчиком непрочитанных.
- **Автопереподключение**: если связь пропала, инициатор пытается восстановить её 5 минут (1,5 → 3 → 5 → 10 → 20 → 30 с). Неотправленное уходит заново, повторы отбрасываются по id.
- **Проверка связи** (`ping` раз в 10 с): «зависшее» соединение распознаётся за 30 с.
- **Уровень сигнала (RSSI)** у найденных устройств и пометка «рядом» у знакомых.
- **Скрытие наушников, часов, колонок** в списке (меню → «Показывать все устройства»).
- **Направление и расстояние** до присланной точки — стрелка по компасу и азимут, без интернета (`DirectionDialog.kt`).
- **Открытие точки в любых картах** через `geo:` — подхватят офлайн-карты (Organic Maps, OsmAnd); Яндекс Карты остались отдельным пунктом.
- **SOS**: красная кнопка в чате. Тревога уходит сразу с последней известной точкой, следом — свежие координаты. У получателя — громкое уведомление (канал «Тревога SOS») и окно с кнопкой «Направление».
- **Голос и рация** (личные чаты): кнопка микрофона рядом с «отправить, где я». Короткое нажатие — запись голосового сообщения (таймер, ✕ и ➤), удержание — рация (говорите, пока держите кнопку; у собеседника звук играет сразу, даже при выключенном экране). Голосовое лежит в ленте с кнопкой «воспроизвести», полосой и длиной. Кодек AMR-WB (`MediaCodec`), см. `VoiceRecorder.kt`, `VoiceTransfer.kt`, `VoicePlayer.kt`, `VoiceStore.kt`.
- **Иконка приложения**, все тексты вынесены в `strings.xml`.
- **Gradle Wrapper** (`./gradlew`), сборка в GitHub Actions через него + запуск тестов протокола.
- **Тесты протокола** (`app/src/test/.../ProtocolTest.kt`).

## Структура

```
App.kt            — общие объекты приложения (настройки, база, уведомления, движок связи)
BtLink.kt         — движок связи: приём/подключение, рукопожатие, подтверждение, ACK, ping, переподключение
LinkService.kt    — фоновая служба, держит связь при свёрнутом приложении
Protocol.kt       — формат кадров и модели данных
ChatRepository.kt — история в SQLite
Prefs.kt          — профиль, id установки, доверенные собеседники
Notifier.kt       — уведомления (служба, сообщения, запросы, SOS)
LocationHelper.kt — геопозиция с точностью и честным возрастом
DirectionDialog.kt— стрелка-направление и расстояние
MapLinks.kt       — открытие точки на карте
Format.kt         — форматирование времени, расстояний, сигнала
VoiceRecorder.kt  — запись с микрофона и сжатие AMR-WB
VoiceTransfer.kt  — передача голоса кадрами, очередь с приоритетами
VoicePlayer.kt    — декодер, проигрывание сообщений и входящей рации
VoiceStore.kt     — файлы звука голосовых сообщений
MainActivity.kt   — интерфейс
Adapters.kt       — списки (чаты/устройства, сообщения)
```

## Как проверено

Здесь не было Android SDK, поэтому полная сборка Gradle не запускалась. Весь Kotlin-код скомпилирован
`kotlinc` против `android.jar` (API 34) с заглушками AndroidX, ссылки на ресурсы сверены; тесты протокола
проходят. **Первую сборку стоит проверить в GitHub Actions или Android Studio, а связь — на двух телефонах.**

## Ограничения и что дальше

- Пока только разговор один на один. Следующие шаги: групповой канал (несколько подключений), пересылка
  по цепочке (mesh) для увеличения дальности, голосовые сообщения → рация (Opus), обнаружение через BLE
  вместо «Стать видимым», «человек не двигается» по акселерометру.
- Дальность телефонного Bluetooth — десятки метров, в лесу меньше.
- `applicationId` — `ru.btmessenger.app` (поменять на свой домен можно в app/build.gradle.kts, см. B6_изменения.md). Старая сборка `com.example.btmessenger` и новая — разные приложения: история не переносится.
- targetSdk и compileSdk 35 (Android 15): отступы под системные панели обрабатываются в `MainActivity.setupInsets()`, см. B7_изменения.md.
